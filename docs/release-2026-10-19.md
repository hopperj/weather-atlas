# October 19, 2026 — Astronomy preview and forecast presentation

## Changes

- Add `/astronomy` and the additive `/api/v1/astronomy/forecast` endpoint: exact
  observing sites, independent saved sites, foreground GPS, model selection,
  Sun/Moon/twilight events, native-time cloud/weather tables, observing criteria,
  explainable windows and a dim red view. Missing or stale weather cannot create
  favourable windows. See [Astronomy](astronomy.md) for methods and limitations.
- Label a zero or missing precipitation amount as **Amount uncertain** when an
  issued positive POP or precipitation condition indicates risk. Preserve actual
  positive values, trace amounts, ranges and source/interval labels; do not infer
  millimetres from a probability. See [Forecast](forecast-page-2026-09-06.md).
- The companion iOS 1.3 (26) build adds Astronomy next to Golf, with Saved and
  Settings under More; saved multiple tee times, chronological cards, Canadian
  course search/pins and usual-course shortcuts; progressive heat outlook faces;
  and hourly/current precipitation and refresh refinements. Its repository has
  separate release and verification notes. These native changes need a new build.

This is a **total-cloud preview**, not a seeing/transparency forecast or the full
layered-cloud roadmap. Android implementation and local verification are noted
in the Astronomy guide; its local directory is not a Git repository and is not
part of the two repository pushes in this release.

## Compatibility and deployment scope

The new endpoint is additive: released mobile clients keep their existing
contracts. No database migration, new ETL, subscriber identity, data copy, routing
change or collector restart is required. Weather is sampled read-only from the
already registered NAS-backed COGs. The API image installs pinned
`astronomy-engine==2.1.19` and `tzfpy==2.1.1` dependencies.

Production target: **sparky**, `/home/hopperj/weather-atlas`. Pull the reviewed
`main` commit, build only `weather-api` and `frontend`, then recreate only those
two services with `--no-deps`. Do not use the whole-stack startup/migration script
for this update. Rollback is a reviewed previous code/image deployment of these
services; there is no schema change to reverse.

Pre-deployment inspection on 2026-10-19 confirmed a clean production checkout,
healthy running services and the NFS mount
`databanks.iolan:/volume1/data/weather-atlas-data` at the production `data` folder.
A uniquely marked public HTTPS request appeared in sparky's Caddy access log,
confirming that the public hostname reached sparky at this check; no routing was
changed. This supersedes the older September migration routing observation for
this dated check only.
